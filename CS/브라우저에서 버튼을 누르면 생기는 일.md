# 브라우저에서 버튼을 누르면 생기는 일
문득 그런 생각을 했다. 브라우저에서 버튼을 눌렀을 때 나는 정확하게 내부 과정을 설명할 수 있는가?

단순히 클라이언트 요청이 백엔드 서버로 넘어가 웹서버 > WAS > DB로 이어지는 단순 3 Tier 과정만을 설명할 수밖에 없는 것은 아닌가라는 고민을 하였고,

글로 정리하려고 보니 각 단계를 세부적으로 알지 못하고 있던 것이다. (만 3년이 다되어가는 마당에... 심각하다)

그래서 지금 각 단계별로 세부적인 항목을 파보려고 한다.

하지만 브라우저 > 네트워크 > 인프라 > 서버 > 디비 등 모든 과정을 다 세세하게 설명하기에는 양이 방대하다는 것을 누구나 알고 있을 것이다.

때문에 모든 과정을 설명하되, 핵심만 짚고 넘어가려고 한다.

## ✔️ 2단계(브라우저) : HTTP 요청 생성

### Tip : OPTIONS Preflight란?
```
브라우저가 "진짜 요청 보내도 돼?"하고 서버에 먼저 허락을 구하는 사전 요청이다.

만약 크기 10000짜리 Array를 body에 담아서 보내는 요청이 있다고 가정했을 때,

만약 CORS 정책을 위반하는 요청이라면 불필요하게 모든 데이터를 보내는 상황이 만들어지게 된다.

이를 방지하기 위해 서버에 예비요청을 통해 유효한 요청인지 확인하는 작업

----------------------------------------------------------------------------

브라우저: "야 서버야, 나 POST 요청 보내도 돼? Authorization 헤더도 같이 보낼건데?"
서버:     "어, 너 허용된 출처네. 보내도 돼."
브라우저: "ㅇㅋ 그럼 이제 진짜 요청 보낸다."
```

### Tip : CSR과 SSR에서의 CORS는 어떻게 달라질까?
```
CSR : 브라우저가 API 호출
SSR : 서버가 API 호출

CORS는 브라우저의 보안 정책이므로, CSR은 브라우저가 직접 API를 호출하기 때문에 CORS 제약을 받으며,
이를 우회하려면 proxy 설정이 필요하다.

반면 SSR은 서버가 API를 호출하기 때문에 브라우저가 개입하지 않아 CORS가 애초에 적용되지 않는다.
```

## ✔️ 3단계(네트워크) : DNS > TCP > TLS
- DNS 조회 : 브라우저 캐시 > OS 캐시 > DNS 서버 순으로 도메인을 IP 주소로 변환한다.

- TCP 3-way handshake : SYN > SYN-ACK > ACK 과정으로 클라이언트-서버 간 연결을 수립한다.

- HTTPS 사용 시 TLS handshake 추가: 서버 인증서 검증 + 대칭키 협상 후 암호화 채널을 만든다.

### Tip : 페이지를 처음 로드할 때 이미 DNS 조회 + TCP 연결이 완료됐는데 또 DNS조회를 해야하는가?
```
같은 도메인 API 호출일 경우 DNS는 이미 브라우저 캐시에 있어서 조회 자체가 일어나지 않거나 무시할 수준(서브밀리초)

또한 TCP도 HTTP/1.1의 `keep-Alive`나 HTTP/2의 멀티플레싱 덕분에 기존 연결 재사용

즉, DNS > TCP > TLS 전부 스킵 가능

그러나, 다른 도메인 API 호출 시 다시 전 과정이 새로 발생
```

### DNS 재귀 질의 상세 흐름
- 만약 `api.example.com`을 처음 접속 시 브라우저가 DNS를 직접 찾아가는게 아니라, Resolver가 최종 IP를 가져다준다.

브라우저가 직접 전 세계 DNS 서버를 돌아다니는 게 안리ㅏ, Resolver가 대신 발품을 팔아준다.

## ✔️ 4단계(인프라) : 로드밸런서 > 리버스 프록시
- 로드밸런서가 트래픽을 여러 서버 인스턴스에 분산한다.

- 리버스 프록시가 SSL 종료, 정적 파일 캐싱, 요청 압축 처리 후 실제 WAS로 포워딩한다.

- 클라이언트는 실제 서버 IP를 알 수 없어 보안성이 높아지고, 서버는 수평 확장이 쉬워진다.

## ✔️ 5단계(앱 레이어) : 라우터 > 미들웨어 체인
- 프레임워크(Spring/Express/Django)의 라우터가 URL 패턴 + HTTP 메서드를 매핑해 적절한 핸들러를 찾는다.

- 미들웨어 체인이 순서대로 실행된다. - 로깅 > CORS 검증 > JWT 인증 > 입력 유효성 검증
  - 라우팅, AOP(Spring), 인터셉터, 필터 체인 등

- 미들웨어 하나라도 실패하면 이후 체인은 실행되지 않고 즉시 에러 응답을 반환한다.

## ✔️ 6단계(앱 레이어) : Controller > Service > Repository
- Controller : 요청을 DTO로 파싱하고 서비스를 호출한다.

- Service : 핵심 비즈니스 로직 처리 및 트랜잭션 관리한다.

- Repository/DAO : DB 접근 추상화 및 ORM(JPA/Sequelize)이 객체를 SQL로 변환해 쿼리 생성한다.

## ✔️ 7단계(데이터 레이어) : DB 쿼리 실행 > 응답 반환
- Connection Pool에서 DB 커넥션을 빌려 SQL 실행한다.

- 결과 데이터가 역방향으로 흐른다. - DTO > JSON 직렬화 > HTTP Response body

- HTTP 상태코드(200, 201, 400, 401, 500 등)와 함께 응답이 클라이언트로 전송
