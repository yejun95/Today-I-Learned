# 브라우저에서 버튼을 누르면 생기는 일
문득 그런 생각을 했다. 브라우저에서 버튼을 눌렀을 때 나는 정확하게 내부 과정을 설명할 수 있는가?

단순히 클라이언트 요청이 백엔드 서버로 넘어가 웹서버 > WAS > DB로 이어지는 단순 3 Tier 과정만을 설명할 수밖에 없는 것은 아닌가라는 고민을 하였고,

글로 정리하려고 보니 각 단계를 세부적으로 알지 못하고 있던 것이다. (만 3년이 다되어가는 마당에... 심각하다)

그래서 지금 각 단계별로 세부적인 항목을 파보려고 한다.

하지만 브라우저 > 네트워크 > 인프라 > 서버 > 디비 등 모든 과정을 다 세세하게 설명하기에는 양이 방대하다는 것을 누구나 알고 있을 것이다.

때문에 모든 과정을 설명하되, 핵심만 짚고 넘어가려고 한다.

## ✔️ 1단계 : 브라우저에서 버튼 클릭
- 사용자가 버튼을 클릭 > 브라우저가 해당 DOM 요소에 click 이벤트를 발생시킨다.

- addEventListener로 등록된 콜백이 이벤트 루프의 Call Stack에 올라가 실행된다.

## ✔️ 2단계 : HTTP 요청 생성
- `fetch() / axios` 호출 시 메서드 (GET/POST 등), URL, 헤더(Content-Type, Authorization), body를 조합해 요청 객체 생성

- 다른 출처(도메인-포트)로 요청 시 브라우저가 CORS 정책을 확인

- 요청 데이터는 `JSON.stringify()` 등으로 직렬화되어 HTTP 패킷 body에 담긴다.

### Tip : OPTIONS Preflight란?
```
브라우저가 "진짜 요청 보내도 돼?"하고 서버에 먼저 허락을 구하는 사전 요청이다.

만약 크기 10000짜리 Array를 body에 담아서 보내는 요청이 있다고 가정했을 때,

만약 CORS 정책을 위반하는 요청이라면 불필요하게 모든 데이터를 보내는 상황이 만들어지게 된다.

이를 방지하기 위해 서버에 예비요청을 통해 유효한 요청인지 확인하는 작업

----------------------------------------------------------------------------

브라우저: "야 서버야, 나 POST 요청 보내도 돼? Authorization 헤더도 같이 보낼건데?"
서버:     "어, 너 허용된 출처네. 보내도 돼."
브라우저: "ㅇㅋ 그럼 이제 진짜 요청 보낸다."
```
